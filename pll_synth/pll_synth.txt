basic pll/synth implementation of old mathcad worksheets

PLL run configurator and saved-data viewer (2026-10-31)
Generated by GitHub Copilot under Lance Lascari's direction.

Development policy (see ../AGENTS.md): GNU Octave first, with MATLAB
compatibility as a goal. Maintain and perform MATLAB compatibility tests
when they do not slow development; MATLAB use is authorized on this computer.
Use focused/parallel checks and record deferred coverage rather than blocking
Octave progress.

From pll_synth/ in the Octave GUI command window:
    bb_pll_setup_gui

Choose a section on the left; all edits are retained when switching sections.
The defaults and generated parameter layout come from aa_RunPllDesign_XXXX.m.
Numeric fields accept literals, lists such as [1000 2000 4000], and ranges
such as 1000:1000:4000. They do not execute arbitrary Octave expressions.
Disabled manual fields retain their values. Reference file mode replaces
reference noise only (F_tcxo_Hz is still used); VCO file mode replaces noise
and Kvco, not the requested output frequency. Noise MAT files must contain
pn_struct with increasing row-vector f and matching row-vector n; see
../pn/pnformat.txt. The original endpoint extension behavior is retained.

The final controls are "Run the script" and "Enable data viewer after run".
Run is initially unchecked. Generate the script, then either keep editing,
exit, or have it run immediately. Generated scripts keep explicit inputs,
existing comments and ordering, plus visible run_options_s settings.
Generated scripts are heavily commented like copied-and-edited examples:
every editable setting has a nearby explanation of its units/role, with
additional guidance for file modes, overrides, sweeps, exports and metrics.
Relevant original inline comments are retained; the old blanket file-metadata
override note is clarified to match the actual reference/VCO input behavior.
They carry a Copilot-under-direction header rather than implying that the
generated implementation was human-written. For a single pass, pn_struct,
int_noise, EVM_tot and residual_FM_Hz are also exposed in the run workspace.
Run the saved aa_run_user_config_... script by name from its directory.
It retains the original clc/close-all/clear startup behavior.

Last GUI fields (including unfinished entries), selected section, script
name and final checkboxes are saved locally in _pll_setup_last.mat on edits
and normal exit, and restored on launch. This file is ignored by the existing
_*/output ignore rule; it is not committed or automatically shared.
"Reset everything" confirms before restoring all fields to runner defaults.
An optional bb_pll_setup_gui(state_filename) argument isolates state for
testing or another local setup history; the directory must already exist.

Single pass is the default. For a sweep, enable bRunSweep in Run / sweep,
select a design target and enter its values. Supported targets: bandwidth,
phase margin, PFD frequency, charge-pump current and output frequency.
At every point, synthesize first, then apply the SAME selected component
overrides. A bandwidth sweep with fixed third-pole R3/C3 is supported; a full
component override with a bandwidth/phase-margin target sweep is rejected
because those targets cannot change the fixed filter. Component-tolerance
sweeps are not part of this version.

Turn off bShowCorePlots and bSaveFigs for large sweeps unless you want the
original analysis figures for each point. The viewer checkbox independently
controls post-run browsing. PDF/JPG exports explicitly select file drivers
(-dpdf/-djpeg) and figure handles; they do not use the system printer.
Outputs are relative to the generated script,
unless def_filename specifies an absolute results directory:
    <basename>_data.mat          reloadable single/sweep dataset
    <basename>_cases/            per-point pn_struct MAT/CSV/figure exports
Results are checkpointed before execution and after each point. Pending and
failed points remain identifiable. Existing datasets/case directories are
protected unless bOverwriteResults is explicitly enabled; choose a new
basename for a new experiment. Overwriting fewer points does not remove
older per-point files; the new dataset is the authoritative point list.

Open the viewer separately, without rerunning analysis:
    cc_pll_data_viewer
    cc_pll_data_viewer('path/to/<basename>_data.mat')
The viewer also accepts an in-memory pll_data_s structure. Surface/contour
and summary views include all completed points; the selector supports
individual-point details and Ctrl-selection for overlays. Views include
phase-noise surfaces/3-D contours, noise contributors and selected offsets,
integrated RMS phase error/EVM, residual FM, requested/achieved bandwidth and
phase margin, component values, settling estimates and cycle slips.
Both transient models have surfaces/3-D contours and individual overlays;
nonlinear PFD phase error is available separately. Transient surfaces show
signed frequency error versus time and swept value, resampled for display
to at most 1000 times over their common time span. Full traces remain saved.
One-point datasets show curves instead of surfaces.

The dataset embeds input/effective settings, components, noise curves and
file-backed source noise; browsing does not require original noise files.
Integration uses the existing resampling and integration methods. EVM is a
small-angle estimate. Residual FM retains its author's unverified/flaky-method
warning; do not treat it as a newly validated calculation. Settling is not a
guaranteed hardware lock time; disabled and not-settled statuses are distinct,
with missing summary markers rather than fabricated zero-time results.

Focused offline regression, from the repository root (Qt/display required):
    octave --no-init-file --no-site-file --no-gui --quiet --eval "addpath('pll_synth'); test_pll_run_tools();"
    matlab -batch "addpath('pll_synth'); test_pll_run_tools();"
Tests use temporary outputs/state, not local measurement data or hardware.

Optional small-signal transient analysis is available in rfdude_pll_oct_0p1.m.
Set pll_inputs_s.bDoTransient=1 to enable it. Configure transient_delta_f_Hz
(starting VCO frequency offset from the target), transient_tmax_s,
transient_points, and transient_ftol_Hz in aa_RunPllDesign_XXXX.m.

The time-domain state-space calculation estimates frequency settling after a
small frequency step. It includes a first-order Pade approximation of the
phase-detector half-reference-period delay, but does not model PFD/charge-pump
saturation, cycle slips, VCO tuning limits, or nonlinear acquisition. Treat
the result as a settling estimate, not a guaranteed lock time. Its reported
settling time is measured on the requested sample grid; increase
transient_points if finer time resolution is needed. The historical Mathcad
worksheet PDF documents the earlier pole/residue method and its limitations.

Optional nonlinear (large-signal) transient analysis is also available. Set
pll_inputs_s.bDoTransientNonlinear=1 to enable it; it is independent of
bDoTransient and reuses transient_delta_f_Hz, transient_tmax_s and
transient_ftol_Hz. Additional settings: transient_nl_steps_per_ref (time
steps per reference period, >=10, default 100) and transient_nl_fvco_min_Hz /
transient_nl_fvco_max_Hz (absolute VCO tuning range, -Inf/Inf = unlimited).
It simulates a tri-state PFD and charge pump driven by reference/divider edge
timing, the actual C1/R2/C2/R3/C3 loop filter, and the VCO phase, so it shows
PFD saturation, cycle slips (counted and reported), reference-rate ripple on
the tuning voltage, and VCO tuning-range limits. The filter is advanced exactly
(matrix exponential) each step and the charge-pump current is averaged over
the PFD pulse widths within a step, so charge is conserved. Not modeled: PFD
reset delay/dead zone, charge-pump mismatch, leakage or compliance limits,
divider/VCO noise. When bDoTransient=1 as well, the small-signal response is
overlaid for comparison. The settling time uses the instantaneous VCO
frequency, which includes reference-rate ripple, so it can be somewhat longer
than the small-signal estimate even for small steps.
