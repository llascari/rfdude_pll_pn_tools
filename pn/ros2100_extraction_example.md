# ROS-2100-119+: complete datasheet-to-data example

Generated by GitHub Copilot under Lance Lascari's direction, 2026-10-31.
GNU Octave first; MATLAB compatible.

## Purpose and source

This example extracts a standalone VCO's frequency-dependent phase noise and
tuning sensitivity, constructs the [version 1 profile](pnformat.md), and saves
an ordinary legacy `pn_struct` for existing tools. It is a reference example
to give an LLM along with another datasheet, not a device simulator.

Source: Mini-Circuits **ROS-2100-119+**, not an unspecified ROS-2100 variant.
The supplied two-page PDF is `ROS-2100-119+.pdf`, marked NON-CATALOG,
REV. E / M176828 / EDR-7662/1 / ROS-2100-119+ / 191223 on printed page 1.
PDF and printed page numbers coincide.

Source SHA-256:
`b5d00f4dbaed62af625a47ddcc5056ba26dc950b333853a04b0c5fbb349808e8`.
The source PDF stays outside the repository; the generator needs no PDF,
network connection, graph-digitization package, or LLM at runtime.

Both pages were rendered and visually checked against extracted PDF text.
Use the nominal +25 C data only; temperature is not a profile dimension.
Page 1 specifies an 8 V supply and a 50 ohm system. Page 2's footnote states
25 C unless mentioned otherwise. These are typical characterization values,
not new guaranteed limits or hardware measurements.

### 3. Derived gain for the detailed curve

The detailed curve's carrier is **1725 MHz**, not the nearby band row's
**1727 MHz**. Its exact Kvco and Vtune are not tabulated. The user approved
explicit interpolation, so derive only the missing gain:

```text
weight = (1725 - 1666.4) / (1727.0 - 1666.4)
Kvco_MHz_per_V = 62.59 + weight * (62.85 - 62.59)
               = 62.8414191419142
Kvco_Hz_per_V  = 62841419.1419142
```

This is a linear model versus operating frequency, **not** a measured Kvco
at 1725 MHz. The detailed point's `comment` identifies the derivation and its
two sources. Vtune remains unspecified. Do not replace 1725 by 1727 or apply
the detailed offset curve unchanged to every operating frequency.

## Limitations that remain visible

- Page 1's electrical-specification band is **1350-2100 MHz**, whereas page
  2's characterization runs **1041.5-2187.1 MHz**. Retain the actual table
  frequencies but do not interpret them as an expanded guaranteed band.
  The profile selector bounds its modeling to stored characterization; it
  does not certify operation outside the electrical specification.
- Page 1's generic noise values (`-76, -102, -123, -143` dBc/Hz) and tuning
  range (`46-72` MHz/V) do not assign an exact carrier point. They are
  cross-checks, not replacements for page 2's frequency-specific evidence.
- The 20 band curves have only four supplied offset points. They do not have
  the detailed trace's 20 measured offsets. Interpolating a denser grid does
  not add measurements. No supported offsets below 1 kHz or above 1 MHz
  are exported.
- No phase-noise measurement uncertainty is specified here. Do not assign
  a fabricated uncertainty to printed values or claim hundredth-dB accuracy.
- The gain derived at 1725 MHz is approximate. Carrier interpolation that
  brackets this point inherits its derived gain and distinct curve evidence.

## Generate, save, and use the data

From the repository root:

```sh
octave --no-init-file --no-site-file --no-gui --quiet --eval "addpath('pn'); aa_generate_ros2100_example;"
matlab -batch "addpath('pn'); aa_generate_ros2100_example;"
```

The [heavily commented generator](aa_generate_ros2100_example.m) is the final
code reference. Its editable settings select the representative frequency,
exact/interpolated selection, output filename, overwrite protection and
optional phase-noise and tuning-sensitivity plots. It works from any directory
after adding `pn/` to the path. Running creates `pn/datfiles_local/` if needed.

Default output: `pn/datfiles_local/ROS_2100_119_profile.mat`, an ignored local
file in MATLAB v7 format. It contains:

- `pn_profile_s`: version 1 wrapper with 21 ordered scalar points (20 band
  curves plus the distinct detailed 1725 MHz point), provenance and default
  representative index 12.
- `pn_struct`: the detailed 1725 MHz curve, with derived Kvco and all seven
  legacy fields unchanged in meaning.
- `selection_s`: which profile point was exported.

The current interactive settings enable saving, overwrite and plotting, so
you can rerun the script after editing parameters. Set `bOverwriteData=0`
to protect an existing output; set `bSaveData=0` for memory-only work.
Rerunning replaces this script's previous plots and leaves unrelated figures
alone. Plot labels show only carrier frequencies in two columns; stored
source names are unchanged, and the shared plot helper displays names literally
instead of interpreting underscores as subscripts.
The second plot shows the 20 tabulated Kvco values versus carrier frequency
in MHz/V versus MHz, with the derived gain at 1725 MHz marked separately.

```matlab
addpath('pn');
data = load('pn/datfiles_local/ROS_2100_119_profile.mat');

% Existing consumers can keep their legacy variable.
pn_struct = data.pn_struct;

% Exact frequency retains the tabulated point and its provenance.
[pn_struct,selection_s] = select_pn_profile(data.pn_profile_s,1727e6);

% Explicitly request a modeled point; no carrier/offset extrapolation.
[pn_struct,selection_s] = select_pn_profile(data.pn_profile_s,1800e6,'interpolate');
save('selected_1800_MHz.mat','pn_struct','-v7');
```

That last export can be supplied to an existing PLL file-input workflow.
The historical loader and GUI still load the scalar only. The programmatic
runner additionally accepts `run_options_s.vco_profile_s` with VCO file mode
enabled: it selects at each requested VCO carrier, rather than reusing the
representative export. The profile's stored representative remains its
default; selecting another curve does not mutate it.

## Shipped datasheet-to-PLL demonstration

Run [demo_2026](../demo_2026.m) from the repository root in a graphical
Octave/MATLAB command window. It prints provenance, regenerates the profile
and both source plots, then waits for a keypress before launching
[aa_demo_ROS_based_synthesizer_runPLL](../pll_synth/aa_demo_ROS_based_synthesizer_runPLL.m).
No PDF or external LLM is needed at runtime. Set `demo_pause_for_key=0`
for unattended use.

The PLL example synthesizes all filter components at the specified band's
midpoint, 1725 MHz, for a 5 kHz target and default 55-degree phase margin.
It copies the exact calculated C1/C2/R2/C3/R3 into a full override and runs
1350, 1537.5, 1725, 1912.5 and 2100 MHz with that unchanged filter. ROS noise
and Kvco are selected per carrier; achieved bandwidth and phase margin vary.
The center uses the detailed stored trace with derived gain; the other four
points explicitly interpolate neighboring band characterization.

All other chip/reference assumptions remain visible in the PLL script,
along with transient settings, export switches and tweak points. The default
10 Hz-200 MHz analysis grid and 100 Hz-1 MHz integration retain the historical
core's endpoint holding outside the source's 1 kHz-1 MHz noise evidence;
these extensions are modeling assumptions, not extracted data.

Outputs are isolated in ignored `pll_synth/_demo_2026/`, not the normal
`pn/datfiles_local/` output. Reruns replace only this example's source plots
and outputs. The saved sweep embeds the original profile, each selected
scalar/selection evidence, and center settings/components. Its viewer opens
automatically and can be reopened without the source files:

```matlab
addpath('pll_synth');
cc_pll_data_viewer('pll_synth/_demo_2026/_ROS_based_synthesizer_data.mat');
```

The generator accepts an optional calling-workspace `ros_example_options_s`
containing only `bSaveData`, `bOverwriteData`, `bPlotData`, and/or
`output_filename`. The root demo uses this to choose its own output without
editing extraction rows; clear the options after calling the generator.
